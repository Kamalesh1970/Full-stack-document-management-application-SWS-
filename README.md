# Document Assistant

A small full-stack app to upload text documents, manage them, and ask questions about them.
Answers are generated by an LLM using the most relevant documents as context, and every answer
shows which documents it came from.

- **Backend:** Python, FastAPI, MongoDB (document metadata + extracted text), uploaded files on local disk
- **Frontend:** React + Vite
- **Search:** BM25 keyword ranking (no embeddings or vector DB)
- **LLM:** any OpenAI-compatible API, OpenRouter by default. Works without a key using mock answers.

## Features

- Upload `.txt`, `.md` and `.json` files (max 5 MB). Files are validated, stored on disk, and their text is extracted and saved.
- List documents (newest first), download them, delete them (removes both the record and the file).
- Chat: ask a question, get an answer plus the source documents used.
- Clear errors for wrong file types, empty/binary files, invalid JSON, missing file, invalid or unknown document ids, and empty questions.
- Interactive API docs (Swagger) at `/docs`, OpenAPI spec at `/openapi.json`.

## Running locally

Needs **Python 3.10+**, **Node.js 20+** and a **MongoDB** database: either MongoDB running locally
(`mongodb://localhost:27017`) or a free [MongoDB Atlas](https://www.mongodb.com/atlas) cluster.

### 1. Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env             # set MONGODB_URI, and LLM_API_KEY for real AI answers
uvicorn app.main:app --reload --port 8000
```

API: http://localhost:8000 · Docs: http://localhost:8000/docs

### 2. Frontend

```bash
cd frontend
npm install
cp .env.example .env             # VITE_API_URL=http://localhost:8000
npm run dev
```

Open the URL Vite prints (usually http://localhost:5173).

## Configuration

`backend/.env`

| Variable | Default | What it does |
|---|---|---|
| `LLM_API_KEY` | empty | OpenRouter (or other OpenAI-compatible) key. Empty = mock answers |
| `LLM_API_BASE` | `https://openrouter.ai/api/v1` | Base URL of the chat completions API |
| `LLM_MODEL` | `openrouter/free` | Model name |
| `MONGODB_URI` | `mongodb://localhost:27017` | MongoDB connection string (local or Atlas) |
| `MONGODB_DB` | `document_assistant` | Database name |
| `DATA_DIR` | `data` | Folder where uploaded files are stored (`data/uploads`) |
| `MAX_FILE_SIZE_MB` | `5` | Upload size limit |
| `CORS_ORIGINS` | `*` | Allowed frontend origins, comma separated |

`frontend/.env`

| Variable | Default |
|---|---|
| `VITE_API_URL` | `http://localhost:8000` |

## API

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/documents` | Upload a file (multipart form field `file`) |
| `GET` | `/api/documents` | List documents, newest first |
| `GET` | `/api/documents/{id}` | Get one document's metadata |
| `GET` | `/api/documents/{id}/download` | Download the original file |
| `DELETE` | `/api/documents/{id}` | Delete the document and its file |
| `POST` | `/api/chat` | Ask a question: `{ "question": "..." }` |
| `GET` | `/api/health` | Health check |

Example chat response:

```json
{
  "answer": "Employees are entitled to 24 days of paid annual leave per year.",
  "sources": [{ "_id": "66f3c1a2b4d5e6f708192a3b", "originalName": "leave-policy.txt" }],
  "provider": "llm"
}
```

Errors come back as `{ "detail": "message" }` with status `400` (bad input), `404` (not found),
`502`/`503` (LLM provider problems).

## How question answering works

```
Upload -> validate -> save file to data/uploads -> extract text -> store metadata + text in MongoDB
Question -> split docs into paragraphs -> BM25 score each paragraph
         -> keep the best paragraphs (weak matches dropped)
         -> send them + the question to the LLM
         -> return answer + the documents those paragraphs came from
```

- Text is lower-cased, split into words, common stop words removed, simple plural stemming.
- BM25 gives rare words more weight than common ones, so a word like "employee" that appears
  everywhere doesn't pull in unrelated documents.
- Up to 5 paragraphs from at most 3 documents go into the prompt.
- If nothing matches, the API says so without calling the LLM.
- Without `LLM_API_KEY`, the "mock" answer lists the sentences that best match the question,
  clearly labelled as a mock answer.

## Project structure

```
backend/
  app/
    main.py            FastAPI app, CORS, error handling
    config.py          settings from .env
    db.py              MongoDB access (pymongo)
    schemas.py         request/response models (used for the OpenAPI docs)
    routers/
      documents.py     upload, list, download, delete
      chat.py          question answering
    services/
      search.py        BM25 retrieval
      llm.py           LLM call + mock fallback
frontend/
  src/
    App.jsx
    api.js             all backend calls, reads VITE_API_URL
    components/
      UploadForm.jsx
      DocumentList.jsx
      ChatPanel.jsx
```
